# Демонстрация на Render Free и Neon Free

[Открыть приложение](https://digital-deanery.onrender.com/) · [Исходный код развёрнутой версии](https://github.com/AiratBastanov/MGIMOSlop/commit/41c0f7bf8f33e07ab862aa1b14d71d0b197cdd93)

Один веб-сервис обслуживает Django и готовую сборку React. Учётные записи, сессии, учебные факты, консультации, фото и файлы работ хранятся в отдельной PostgreSQL. Начните показ со страницы входа. Войдите как `student_a`, найдите «Расписание», откройте оценки и отправьте заявку. В другом профиле браузера войдите как `staff_demo`, сохраните ответ и вернитесь к заявке студента. Преподавателю доступна проверка отправленной версии работы.

## Перед созданием ресурсов

Владелец проверяет в Render **Billing** выбранного рабочего пространства, включённый трафик и минуты сборки. Для этой установки подходит бесплатное рабочее пространство без привязанного способа оплаты. При исчерпании трафика такой сервис приостанавливается, при исчерпании минут останавливаются новые сборки. Рабочее пространство с картой может получить счёт за превышение трафика даже при `plan: free`. Если провайдер требует карту или переход на платный план, остановитесь до создания ресурса. [Условия Render](https://render.com/docs/free)

В организации Neon выберите **Free**, отдельный проект PostgreSQL 17 и по возможности AWS Frankfurt рядом с веб-сервисом. Сверьте доступные квоты хранилища, вычислений и передачи данных в консоли. [Тариф Neon](https://neon.com/pricing)

В действующей демонстрации база приложения с файлами и фотографиями занимает 17,8 МБ. Neon сообщил логический размер ветки 46,9 МБ при квоте проекта 1 ГБ на дату проверки. При последующих загрузках следите за расходом всего проекта, включая историю. Исходные пределы загрузки сохранены.

В новом проекте создайте обычную роль приложения через SQL. Роли, созданные кнопкой **Add role**, получают членство в `neon_superuser`. При развёртывании оператор создал SQL-роль `jury_app` с правом входа, сгенерировал случайный пароль и передал его из памяти клиента по соединению с проверкой TLS. Neon отклонил готовый SCRAM-хеш, вычисленный клиентом. Затем владелец выполнил `GRANT jury_app TO CURRENT_USER;` и `CREATE DATABASE deanery_jury OWNER jury_app;`. Роль приложения не имеет прав суперпользователя, создания ролей или других баз. [Роли Neon](https://neon.com/docs/manage/roles)

В **Connect** выберите выделенную БД и роль приложения, отключите **Connection pooling**. Для роли из SQL используйте сохранённый при создании пароль с URL-кодированием специальных символов. Во время подготовки приложение удерживает блокировку на уровне сессии PostgreSQL, поэтому и оператор, и веб-сервис используют прямой endpoint. [Режимы соединения](https://neon.com/docs/connect/connection-pooling)

## Первое заполнение

Команды выполняются оператором из публичного исходного дерева. Пример для Windows и БД с именем `deanery_jury`. Подставьте фактическое имя из Neon. Существующую локальную установку можно оставить запущенной.

```powershell
py -3.14 -m venv .local/hosting-venv
.\.local\hosting-venv\Scripts\python.exe -m pip install -r requirements/render.txt
.\.local\hosting-venv\Scripts\python.exe scripts/prepare_hosted_demo.py --database deanery_jury
```

Вставьте прямой URI в скрытый запрос терминала. Команда также принимает `DATABASE_URL` из защищённого окружения. Она проверяет имя и роль на сервере, наличие `btree_gist` и пустую схему при первой установке. Затем запускает прямые миграции и штатную композицию демонстрации. В конце выводит размер БД в байтах. Учебный набор сохраняет исходные даты ноября–декабря 2026 года. Время первых консультаций выбирается один раз по московскому времени.

Оба файла сохраняются на компьютере оператора в каталоге с ограниченными правами.

| Файл | Кому нужен |
| --- | --- |
| `.local/hosted-demo/service.json` | Оператору. Содержит постоянный ключ Django и прямой URI Neon для закрытых настроек сервиса. |
| `.local/hosted-demo/demo-credentials.json` | Жюри передаются только четыре пары прикладных логинов и паролей из этого файла. |

При прерывании используйте тот же каталог и имя БД. Команда продолжает известную установку. Во время обычной работы запускать заполнение повторно не требуется.

## Запуск и проверка

Действующий сервис `digital-deanery` создан через API Render по параметрам из проверенного Blueprint. Файлы берутся из ветки `main`, обновление запускает оператор в уже существующем сервисе. Для отдельной установки откройте **New → Blueprint**, выберите репозиторий и ветку `main`. В [описании сервиса](../render.yaml) указаны `plan: free`, регион Frankfurt и ручное обновление. Задайте два закрытых значения из `service.json` в полях Render и сохраните ключ при последующих выпусках. [Создание сервиса](https://render.com/docs/deploy-django) · [Спецификация Blueprint](https://render.com/docs/blueprint-spec)

Render сообщает точный домен в `RENDER_EXTERNAL_HOSTNAME`; по нему приложение задаёт разрешённый Host, HTTPS origin для CSRF и адрес ссылок. Публичный HTTP перенаправляет на HTTPS балансировщик Render. У бесплатного сервиса нет входящего трафика из частной сети. Django проверяет Host и использует публичную HTTPS-схему, игнорируя присланные клиентом заголовки адреса и протокола. Gunicorn запускается с одним процессом и двумя потоками на `0.0.0.0:$PORT`. WhiteNoise раздаёт собранную статику. Длительное кеширование получают только файлы Vite с хешем в имени. Почтовый транспорт остаётся локальным, помощник использует готовую справку. [Сеть Render](https://render.com/docs/web-services)

Проверка старта `migrate --check` читает состояние схемы. Частая проверка Render обращается к `/health/live/` без запросов к БД. Для проверки приложения с БД после запуска откройте `/health/ready/`, затем страницу входа. Бюджет установки соединения с Neon составляет 15 секунд, SQL-запроса 10 секунд, ожидания блокировки 5 секунд. Вход ограничен пятью ошибками по логину на 15 минут. Ограничение действует для этого логина со всех адресов. Проверять порог следует на отдельном тестовом имени.

После 15 минут без входящего трафика Render усыпляет бесплатный сервис. 19 ноября после естественного простоя API Render показал ноль работающих экземпляров. При первом открытии Chrome получил страницу ожидания, а через **40,4 секунды** показал форму входа. Это один замер. Провайдер указывает ориентир около минуты. [Условия сна](https://render.com/docs/free) · [Проверки экземпляра](https://render.com/docs/health-checks)

Для браузерной проверки установите на машине оператора зависимости из `requirements/development.txt` и Chrome. Запишите **выданный Render** домен в переменную окружения `RENDER_EXTERNAL_HOSTNAME` и задайте `$url = "https://$env:RENDER_EXTERNAL_HOSTNAME"`. Первая команда создаёт синтетическую заявку, завершает её и сохраняет отзыв. После ручного перезапуска веб-сервиса вторая повторяет входы, читает прежнюю заявку и отзыв и сравнивает SHA-256 двух приватных вложений.

```powershell
.\.local\hosting-venv\Scripts\python.exe scripts/verify_demo.py --hosted --base-url $url --output .local/hosted-demo/before
.\.local\hosting-venv\Scripts\python.exe scripts/verify_demo.py --hosted --base-url $url --after-restart .local/hosted-demo/before/checks.json --output .local/hosted-demo/after
```

## Копия, восстановление и обновление

Сохраните `service.json` и прикладные пароли отдельно в защищённом хранилище. Для этой установки выбирайте утилиты PostgreSQL 17.12 и совместимый сервер восстановления. Полный облачный архив восстановлен в отдельную PostgreSQL 17.12. Предыдущая 17.11 остановилась на параметре столбца `pg_attver`. [Изменения PostgreSQL 17.12](https://www.postgresql.org/docs/release/17.12/)

Используйте прямой endpoint и закрытый `PGPASSFILE`. Запишите в файл строку `host:5432:database:role:password` для каждого разрешённого подключения. На Unix установите права `0600`. Следующий пример для Unix ожидает фактические значения `DB_HOST`, `DB_NAME`, `DB_USER` и путь к закрытому каталогу в `PRIVATE_DIR`.

```sh
umask 077
export PGPASSFILE="$PRIVATE_DIR/pgpass" PGSSLMODE=verify-full PGCHANNELBINDING=require PGCONNECT_TIMEOUT=15
export PGSSLROOTCERT=/etc/ssl/certs/ca-certificates.crt
pg_dump -w -h "$DB_HOST" -p 5432 -U "$DB_USER" -d "$DB_NAME" -Fc -f "$PRIVATE_DIR/deanery.dump"
pg_restore --list "$PRIVATE_DIR/deanery.dump"
```

Проверьте остаток квоты и создайте **новую пустую БД** с отдельной ролью-владельцем и доступным расширением `btree_gist`. Сверьте фактические `current_database()` и `current_user` целевого подключения. Задайте его прямой endpoint, роль и имя в переменных `RESTORE_*`.

```sh
pg_restore -w -h "$RESTORE_HOST" -p 5432 -U "$RESTORE_USER" -d "$RESTORE_DB" \
  --no-owner --no-privileges --exit-on-error --single-transaction "$PRIVATE_DIR/deanery.dump"
```

Откройте восстановленную копию с тем же Django-ключом, проверьте миграции, вход, прежние заявки, отзывы, консультации и байты файлов. JPEG-фото, файлы преподавателя и вложения версий студента находятся в таблицах и входят в дамп. Временные файлы при разборе загрузки расходуют только место на время запроса. Проверяйте занятое место всего проекта и оставляйте запас под загрузки и восстановление. [Резервные копии Neon](https://neon.com/docs/manage/backup-pg-dump)

Перед обновлением сохраните копию, возьмите проверенный коммит и выполните с машины оператора `scripts/prepare_hosted_demo.py --database ИМЯ --migrate-only`. Затем в Render разверните именно этот коммит, сравните его SHA в Events и снова откройте прежнюю заявку. Контейнер читает БД при старте и не изменяет пароли или демоданные.
