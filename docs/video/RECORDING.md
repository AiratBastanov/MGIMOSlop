# Как записана демонстрация

Видео снято настоящим Chrome через Playwright на отдельной синтетической PostgreSQL, с тем же приложением и собранными файлами. Вход выполнен до начала записываемых сцен. Заявка, ответ службы и отзыв преподавателя сохранены через обычные формы; после возвращения и обновления страницы результат проверен. Даты и часы сервера не менялись, ответы API и содержимое интерфейса не подменялись.

Рабочая область desktop — 1920 × 984 пикселя без увеличения готового кадра. Итоговый кадр 1920 × 1080 дополняет её нижней полосой русских подписей, не закрывающей кнопки. Мобильная сцена снята отдельным окном 360 × 800 CSS px и помещена в кадр в исходном разрешении. Это браузерная эмуляция, а не проверка физического телефона.

Монтаж соединяет окна ролей в порядке действий и убирает только подготовку перед каждой сценой. Скорость воспроизведения обычная. Паузы оставлены для чтения; длительность сцен не является измерением быстродействия. Звуковой дорожки нет. Подписи встроены в изображение, доступны также [SRT](demo.ru.srt) и [расшифровка](transcript.ru.md).

## Повторить на отдельном демо

Нужны существующие зависимости из `requirements/development.txt`, установленный Chrome, FFmpeg/FFprobe с H.264 и libass. Проверена FFmpeg 8.0; её бинарники не входят в репозиторий. Сборка приложения описана в [установке](../SETUP.md).

Создайте отдельную папку исходников, новую пустую БД и роль с именем вида `deanery_film_...`, примените миграции и штатный `prepare_demo`. Запустите эту копию с её собственным JSON config и отдельным портом. Не используйте рабочую базу или её пароли. Первый пример задания должен ещё ожидать отзыва; запись сохраняет новые действия и не сбрасывает существующие.

```powershell
python scripts/record_demo.py --base http://127.0.0.1:8001 --credentials .local/demo-credentials.json --output .local/film --synthetic-database deanery_film_example
python scripts/render_demo_video.py --capture .local/film/capture.json --output .local/finished
```

Первый инструмент закрывает записывающие контексты и сохраняет исходные WebM с фактическими временами сцен. Второй создаёт MP4, постер, подписи и сведения о кодеках/хеше; декодирует весь фильм. После этого просмотрите весь итоговый файл по порядку, проверьте читаемость подписей и отсутствие секретов. Сырые записи, снимки ошибок и конфигурация остаются локально. В выпуск загружаются только проверенные итоговые артефакты.
