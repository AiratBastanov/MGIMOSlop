# Установка и запуск

[К описанию продукта](../README.md) · [Демонстрация](DEMO.md) · [Локальный ИИ](AI_ASSISTANT.md)

## Подготовить окружение

Окружение локального запуска — Windows, Python **3.14.10**, PostgreSQL **17.11** и отдельная виртуальная среда. Пакеты закреплены в [runtime requirements](../requirements/runtime.txt); выполненные проверки и их границы перечислены в [описании проверки](VALIDATION.md). PostgreSQL должен включать расширение `btree_gist`, поставляемое со стандартным сервером: оно используется в том числе для защиты от пересечений консультаций. SQLite не поддерживается.

1. Установите Python 3.14 и PostgreSQL 17 из официальных поставок. Запомните порт PostgreSQL и пароль его локального администратора. Для этого проекта используется порт 5548; стандартный порт установщика 5432 также подходит. Не меняйте порт существующей базы ради инструкции.
2. Скачайте исходники через **Code → Download ZIP** либо клонируйте доступную вам ветку репозитория. Откройте PowerShell в корне, где находится `manage.py`.
3. Для новой установки используйте отдельную папку исходников. Не копируйте чужие `.local`, `.venv`, демопароли или наполненную БД.

Это не полностью автономная установка без интернета: pip получает закреплённые пакеты из обычного источника. Модели ИИ не загружаются.

## Первое заполнение

Выполняйте команды по очереди. При ненулевом коде остановитесь, исправьте причину и повторите соответствующий шаг.

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements/runtime.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe scripts/create_local_database.py --database deanery_demo --port 5548
```

Последняя команда интерактивно запросит пароль локального администратора `postgres`. Для другой административной роли добавьте `--admin имя_роли`. Пароль не передаётся аргументом командной строки. Скрипт создаёт **новую** БД и отдельную роль без `SUPERUSER`, `CREATEDB` и `CREATEROLE`, генерирует пароль БД и Django secret и сохраняет `.local/app.json`. На Windows каталог закрывается ACL для текущего пользователя, SYSTEM и Administrators; на Linux — правами `0700`.

Повтор с тем же config только проверяет подключение. Существующая БД или роль без соответствующего config — конфликт: автоматического сброса пароля нет. Если создание прервалось после появления `.pending.json`, сохраните этот закрытый файл и выясните с администратором, какие объекты созданы. Не удаляйте существующую БД ради повторного запуска.

```powershell
.\.venv\Scripts\python.exe manage.py migrate --noinput
.\.venv\Scripts\python.exe manage.py prepare_demo --database deanery_demo
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000 --noreload --insecure
```

Откройте http://127.0.0.1:8000/. Параметр `--database` должен точно совпадать с конфигурацией. `prepare_demo` принимает пустую БД после миграций либо продолжает начатую ею подготовку. Чужой заполненный target и чужой файл демопаролей отклоняются. Команда проверяет учебные пакеты перед каждым импортом и создаёт связанные примеры через существующие сервисы:

- двух студентов с разными факультетами и учебными данными, преподавателя и сотрудника службы;
- расписание, изменения, оценки за три периода, сессию и открытые требования;
- группу с вымышленными участниками, примерами согласия на контакты и ресурсами;
- материал преподавателя с двумя приватными файлами, частный черновик, задания и исправленный ответ;
- объявление службы и заявку с вопросом и ответом на уточнение;
- подготовку к вымышленному обмену, четыре разовых интервала преподавателя и службы и одну подтверждённую учебную консультацию с синтетическим вопросом, связанную с подготовкой.

Состав имеет постоянную версию. Повтор после завершения сохраняет пароли, тексты, решения, отзывы, прочтения, подготовку и записи на встречи. Более новый принятый источник не заменяется старым. Команда не вызывается при входе, открытии страницы или старте сервера.

Учебные даты фиксированы; после 7 декабря 2026 года интерфейс показывает истечение актуальности источника. Для другого периода нужен отдельный проверенный импорт. Время новых демонстрационных консультаций определяется при первом явном заполнении относительно текущей даты по Москве. Повтор команды не переносит уже созданные встречи и не отменяет бронирования. Когда время примеров прошло, преподаватель или служба создаёт новое время через свой кабинет.

```powershell
notepad .\.local\demo-credentials.json
```

Этот локальный файл содержит четыре случайных пароля установки. Демодоступ для будущего размещённого приложения передаётся отдельно.

## Обновить существующую установку

Сохраните защищённую копию PostgreSQL и закрытой конфигурации по [инструкции резервного копирования](../deploy/README.md#резервная-копия-и-восстановление). Остановите свой web-сервер, обновите исходники и собранные ресурсы, сохранив прежние `.local/app.json` и файл паролей. Следующие команды применяются к уже настроенной БД; в примере она называется `deanery_demo`:

```powershell
.\.venv\Scripts\python.exe manage.py migrate --noinput
.\.venv\Scripts\python.exe manage.py prepare_connected_journeys --database deanery_demo
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000 --noreload --insecure
```

Значение `--database` должно совпадать с фактической конфигурацией. `prepare_connected_journeys` — явное добавление связанных демонстрационных примеров к существующим учётным записям. Оно использует постоянные идентификаторы и обычные сервисы; существующие пароли, учебные итоги, частные тексты и сохранённые операции не сбрасываются. Несовместимый ранее созданный пример означает конфликт, который нужно разобрать, а не разрешение заменить его содержимое.

Для самого обновления схемы достаточно `migrate`; примеры добавляются отдельной командой. При обычном перезапуске обе команды не нужны. Создание новой БД из первого раздела к обновлению рабочей установки не относится.

## Обычный перезапуск

Из той же папки, при работающем PostgreSQL:

```powershell
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000 --noreload --insecure
```

Остановить свой локальный сервер можно `Ctrl+C` в его терминале. Не запускайте второй экземпляр на занятом 8000. При перезапуске не нужны заполнение демо, Node или Vite. База и `.local/app.json` остаются прежними.

`runserver --insecure` служит для локальной раздачи собранной статики при `DEBUG=False`. Это режим разработки. Схема Linux/Gunicorn/Caddy и её проверенные границы описаны [отдельно](../deploy/README.md).

## Как читается конфигурация

Приоритет: переменные окружения, затем JSON по `DEANERY_CONFIG`, затем значения по умолчанию. Без `DEANERY_CONFIG` используется `.local/app.json` текущего проекта. [.env.example](../.env.example) — справочник: файл **не загружается автоматически**.

Для явного выбора конфигурации:

```powershell
$env:DEANERY_CONFIG = (Resolve-Path '.local/app.json').Path
```

Для первого заполнения другой БД используйте отдельную папку исходников и её собственный credential-файл. Старые переменные `DB_NAME`, `DB_USER`, `DB_PORT` имеют приоритет над JSON. Не печатайте `DB_PASSWORD` и `DJANGO_SECRET_KEY` в журнал.

| Настройка | Назначение |
| --- | --- |
| `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` | Точная PostgreSQL-цель и роль приложения |
| `DJANGO_SECRET_KEY` | Случайный секрет установки; сохраняется при обновлении |
| `PUBLIC_BASE_URL` | Основа ссылок в письмах, локально `http://127.0.0.1:8000` |
| `SUPPORT_*` | Необязательный провайдер, [инструкция](AI_ASSISTANT.md) |
| `MAIL_EXTERNAL_ENABLED` | По умолчанию `0`; письма сохраняются локально |

## Пересобрать интерфейс

Готовые файлы включены в репозиторий. Для изменений проверена среда Node **22.20.0**, npm **10.9.3**; допустимая ветка Node — `>=22.12 <23`.

```powershell
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run build -- --configLoader runner
```

Команда выполняет TypeScript-проверку и Vite-сборку. Источники — `frontend/src` и `static/app.css`; результат — `static/frontend/manifest.json` вместе со всеми перечисленными JS, CSS и шрифтами. После изменения кода перезапустите свой Django. Отдельного Vite-сервера нет.

Коррекция связи подготовки с консультацией и отбора поиска не меняет зависимости или схему БД. Для существующей установки достаточно обновлённого кода, собранных assets и обычного перезапуска своего web-процесса. Повторное заполнение демо, сброс БД и запуск модели для этого не нужны. Старые личные связи автоматически читают последнее звено переноса.

## Если не работает

| Симптом | Что проверить |
| --- | --- |
| PostgreSQL не отвечает | Работает ли служба, совпадают ли порт, имя и роль в JSON и окружении |
| «Нужна пустая БД» | Не направлена ли первичная подготовка на рабочую базу; используйте новую цель |
| Конфликт состава демо | Сохраните сообщение; не редактируйте принятые hashes и не применяйте старый импорт поверх нового |
| Нет оформления | Наличие manifest и его файлов, локальный флаг `--insecure`, перезапуск после сборки |
| ИИ не подключён | Кабинет продолжает работу; см. [статусы и восстановление](AI_ASSISTANT.md#статусы) |
| Много попыток входа | Проверьте файл паролей; ограничение пары логин/IP действует 15 минут. Не проверяйте блокировку на аккаунтах жюри |
| Учебные сведения не подтверждены | Дату, полноту и актуальность источника; это отдельная проверка от готовности БД |
| Нет будущего времени консультаций | Не истекли ли даты примеров и есть ли у принимающей стороны действующее назначение; новое время открывается явно в кабинете |
| «Время уже занято» | Откройте актуальные доступные интервалы; сообщение об успешной записи появляется только после сохранения |

`/health/ready/` проверяет доступность БД и полноту миграций. Он не обращается к Ollama и не создаёт данные. Резервная копия включает PostgreSQL и отдельно закрытую конфигурацию; [восстановление — только в новую БД](../deploy/README.md#резервная-копия-и-восстановление).
