# Проверки и их границы

[Запуск](SETUP.md) · [Демонстрация](DEMO.md) · [Процесс создания](DEVELOPMENT_PROCESS.md)

Проверки выполнены 12–13 ноября 2026 года на Windows: Python 3.14.10, Django 5.2.19, PostgreSQL 17.11, Chrome 157.0.8103.51, Playwright 1.64.1. Frontend пересобран с Node 22.20.0 и npm 10.9.3. Для новой поставки создана отдельная виртуальная среда и пустая БД с отдельной ролью. Авторская БД не служила источником установки.

## Поиск, подготовка и консультации

Перед локальным выпуском выполнена адресная коррекция связанного пути. Новые PostgreSQL-проверки подтверждают атомарное бронирование с личной связью, повтор после потери ответа, откат сбоя связи и неудачного переноса, прежний ручной якорь, A→B→C, отмену C, несколько явных подготовок и отсутствие раскрытия плана ведущему. Проверка поиска через HTTP использует более 200 разрешённых публикаций и отдельную границу консультаций; редкое название за прежним префиксом находится, чужой и неопубликованный двойники не меняют выдачу. Проверяются ограничение совпадений, сужение запроса, нормализация и стабильные страницы. Число SQL-запросов измеряется в этом наборе, не объявляется нагрузочным тестом.

Новый проход Chrome выполняет подготовка → выбор времени → подтверждение → возврат → два переноса → возврат → отмена. Потеря ответа управляемо воспроизводится после реального сохранения. Отдельные сессии студента, службы, преподавателя и второго студента проверяют доступ; 360 px сохраняет ввод/фокус/прокрутку при обычной проверке. Firefox проверяет затронутые страницы на 360/320 px, клавиатуру и увеличение размера текста до 200%. Маршрут «Найти все оценки» показывает 22 внесённых результата с правильным фильтром, невнесённый итог доступен отдельно. Это автоматизация на синтетических данных; физические устройства и реальная пользовательская оценка не проверены.

Зависимости и миграции этой коррекцией не меняются. Прежнее доказательство чистой установки применимо в своих границах; переустановка, полный исторический suite, импорт, инспектор файлов, восстановление и инфраструктурные проверки повторно не выполнялись. Локальная модель оставалась выключенной. Три новые подлинные иллюстрации включены в [документ процесса](creation-process.pdf); исторические снимки сохранены.

Неудачные промежуточные попытки сохранены в рабочем архиве. Среди исправлений — слишком низкий приоритет поискового действия, фокус под помощником, три пограничных случая из дополнительного чтения исходников и ошибки самих проверочных скриптов. Повторный запуск затронутого случая не считается новым независимым покрытием.

Сравнение маршрутов было наблюдаемым, но не исследованием пользователей: старая форма справки требует два клика; поиск — два клика, ввод и Enter. Сокращение времени или количества действий здесь не заявляется. Польза связанного пути — возвращение к сохранённому плану и явная связь с ответом и встречей. [Протокол для 2–3 реальных участников](RESEARCH_DECISIONS.md#короткая-проверка-с-участниками) подготовлен, участники не привлекались. Сохранены настоящие автоматизированные видеозаписи; они не выдаются за смонтированный конкурсный ролик или измерение скорости человека.

## Повторить локально

Для обычной проверки новой установки:

```powershell
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
```

Для браузера установите инструменты разработчика (они не нужны пользователю кабинета). Нужен установленный Google Chrome; скрипт выбирает `channel=chrome`.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements/development.txt
.\.venv\Scripts\python.exe scripts/verify_demo.py --base-url http://127.0.0.1:8000 --credentials .local/demo-credentials.json --output .local/checks/browser-01 --read-only
```

`--read-only` не создаёт заявку или отзыв; вход и штатные отметки просмотра всё равно могут менять состояние сеанса и уведомлений. Для полного сценария уберите флаг **только в отдельной свежей демонстрации**: будут созданы заявка и отзыв к подготовленной работе. Скрипт требует новый каталог результата. При включённом, но недоступном сервисе добавьте `--provider-state unavailable`. Проверка не выполняет подбор паролей.

## Автоматические проверки на отдельной БД

Нужна заранее созданная отдельная база **`deanery_test` под ролью `deanery_test`**, без административных прав и `CREATEDB`. Её параметры сохраняются в защищённом `.local/test.json`. Не используйте working-базу: специальный test runner выполняет миграции и **очищает содержимое тестовой БД до и после запуска**. Он не создаёт и не удаляет базу автоматически.

`test.json` использует те же ключи `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `DJANGO_SECRET_KEY`, что [основная конфигурация](SETUP.md), но отдельные значения. `deanery.settings.testing` отклоняет любое другое имя БД или роли. Защита не отменяет необходимости проверить host и port: это должна быть выделенная локальная тестовая база.

Для создания новой тестовой БД можно использовать тот же скрипт с отдельным файлом конфигурации:

```powershell
.\.venv\Scripts\python.exe scripts/create_local_database.py --database deanery_test --port 5548 --config .local/test.json
```

```powershell
.\.venv\Scripts\python.exe scripts/run_tests.py --label tests.test_optional_support --label tests.test_demo_setup --label tests.test_task12_workflows.SupportContractTests --log .local/checks/unit-01.log
```

Для изменённых предметных сценариев, на той же отдельной тестовой БД:

```powershell
.\.venv\Scripts\python.exe scripts/run_tests.py --label tests.test_discovery --label tests.test_journeys --label tests.test_consultations --label tests.test_connected_help --label tests.test_demo_setup --log .local/checks/connected-01.log
```

Команда не запускает браузер. Остальные сохранённые серверные тесты находятся в `tests/`; их исторические имена — часть совместимости исходников. Общий запуск `scripts/run_tests.py` требует той же отдельной тестовой БД. Сценарии, завязанные на закрытые браузерные записи, не включены в публичный набор.

## Проверить материалы передачи

`scripts/verify_publication.py` проверяет состав по manifest, локальные ссылки, наличие migrations/fixtures/assets, запрещённые пути и размер файлов. С `--outgoing HEAD` дополнительно проверяет все отправляемые Git blobs, а не только текущие файлы. Частные секреты можно передать через `--secret-file` из закрытых JSON; значения никогда не печатаются. Это адресная проверка, не универсальный детектор любых секретов.

Редактируемый источник документа — [creation-process.html](creation-process.html). Для повторного PDF нужен Playwright и Chrome:

```powershell
.\.venv\Scripts\python.exe scripts/render_creation_process.py --output .local/creation-process-review.pdf
```

Скрипт проверяет загрузку шрифта и изображений, переполнение страниц и создаёт PDF с внутренними ссылками. Для публикации визуально просмотрите **все** страницы; автоматическая геометрия не заменяет чтение.

## Что не утверждается

Свежий положительный inference настоящей Qwen в этой проверке не выполнялся; [история её реального использования](DEVELOPMENT_PROCESS.md#необязательный-ии-и-честный-запасной-режим) описана отдельно. Нет заявления о полном аудите безопасности или доступности, испытаниях физических устройств, текущей полной Linux-установке, внешней почте, публичном хостинге, российском сетевом доступе и завершённой конкурсной подаче.
