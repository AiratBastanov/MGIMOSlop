# Проверки и их границы

## Публичный прототип в российском регионе, 19 ноября 2026

Владелец открыл форму «Войти в кабинет» без VPN через то же российское подключение, на котором не открывался Render. В панели 67hosting подтверждены регион `ru`, тариф Free, 256 МБ памяти и отключённая опция `always_on`. Контейнер использует прежнюю отдельную базу PostgreSQL 17.12 в Neon Free во Франкфурте. Проверка с контейнера подтвердила TLS до прямого endpoint Neon, а HTTP-запрос к домену получил перенаправление 308 на HTTPS. [Открыть прототип](https://digital-deanery-641d.host67.com/) · [Развёрнутый коммит](https://github.com/AiratBastanov/MGIMOSlop/commit/0ae3956c806afe4eed712374eb418eec7fab299a)

Четыре тестовых аккаунта вошли с прежними паролями. Студент открыл «Сегодня», расписание, оценки, уведомления и поиск по слову «Расписание». Факультетская служба ответила на новую заявку № 5, студент прочитал сохранённый ответ. Преподаватель скачал файл с планом консультации и оставил отзыв к первой версии работы. У второго студента запросы чужой заявки, файлов и фотографии получили HTTP 404. Байты двух файлов преподавателя, вложения студента и фотографии совпали с контрольными суммами предыдущего размещения.

Проверены переход на исходную страницу после входа, совпадение файлов CSS, JavaScript и шрифтов с исходной сборкой, пять разделов на ширине 360 px и возврат из режима чтения. У всех ролей помощник показал «ИИ не подключён» и вернул выбранный готовый ответ справки.

У студента открылись свободные интервалы консультаций и его подтверждённая запись. Сайт выставил защищённые cookies. На отдельном тестовом имени пятая неудачная попытка входа вернула HTTP 429 и паузу 900 секунд. Редактор принял через прокси набор из файлов 10, 10 и 5 МиБ и вернул штатный отказ при отсутствии команды сохранения. Содержимое проверки не записывалось в БД.

Тот же коммит повторно развернули на 67hosting. Провайдер зафиксировал сборку и запуск Gunicorn. До и после запуска совпали число строк и SHA-256 всех 83 таблиц. Из нового полного архива восстановили данные в отдельную PostgreSQL 17.12 и сверили их со снимком источника, включая пароли в виде хешей, уведомления, консультации и двоичные вложения. [Резервное копирование и восстановление](../deploy/RENDER.md)

## Первое размещение на Render, 19 ноября 2026

Приложение открылось по HTTPS без входа в Render. Сервис работает во Франкфурте на Render Free, отдельная PostgreSQL 17.12 — в Neon Free в том же регионе. Четыре аккаунта вошли в независимых профилях Chrome. Для каждой роли помощник показал «ИИ не подключён» и вернул выбранный готовый ответ FAQ. [Открыть приложение](https://digital-deanery.onrender.com/) · [Исходный коммит](https://github.com/AiratBastanov/MGIMOSlop/commit/41c0f7bf8f33e07ab862aa1b14d71d0b197cdd93)

Студент нашёл «Расписание» через поиск, открыл оценки и уведомления и оформил заявку № 4. Служба запросила уточнение, получила ответ и завершила заявку. Студент увидел статус «Готова». Во второй проверке преподаватель сохранил отзыв и результат 4 к версии 1 отправленной работы. Второй студент получил HTTP 404 при открытии чужой заявки и обоих файлов из материала другой группы. В кабинете первого студента видны свободные консультации и собственная подтверждённая запись.

JavaScript, CSS, шрифты и значок совпали с файлами опубликованной версии. Проверены перенаправление HTTP на HTTPS, защищённые cookies и длительный кэш для файлов с хешем в имени. На отдельном вымышленном имени пятая ошибочная попытка входа получила HTTP 429 с интервалом 900 секунд. При ширине 360 px доступны пять разделов, сохранение настроек чтения и возврат к обычному виду.

После естественного простоя Render показал ноль экземпляров. Чистое окно Chrome при первом запросе получило страницу ожидания с HTTP 503. Через 40,4 секунды оно показало форму входа с HTTP 200. В журнале Render в это время появился новый процесс Gunicorn.

После повторного развёртывания того же коммита совпали количество строк и контрольные суммы всех 83 таблиц. Четыре пользователя вошли с прежними паролями. Браузер прочитал сохранённые решение службы и отзыв, SHA-256 двух файлов преподавателя совпали. Владелец открыл адрес Render с VPN. При отключении VPN в его сети сайт не открылся.

Преподаватель также опубликовал «План учебной консультации». Студент отправил текстовый файл вместе с первой версией работы, преподаватель скачал его из этой версии. После отдельного перезапуска Render совпали байты студенческого файла и фотографии из каталога группы. Для второго студента обе ссылки вернули HTTP 404. Полный архив PostgreSQL 17.12 восстановлен в новую изолированную базу. Число строк и контрольные суммы всех 83 таблиц совпали со снимком источника, из которого был сделан архив. [Резервное копирование](../deploy/RENDER.md)

## Образ для хостинга, 19 ноября 2026

В локальной сети Docker запущены Linux, Gunicorn и PostgreSQL 17.11 с проверкой TLS-сертификата и имени сервера. Веб-процесс работал с лимитами 512 МиБ и 0,1 CPU. Обычная роль PostgreSQL применила миграции, включая `btree_gist`, и подготовила отдельную БД объёмом 17 389 235 байт. Браузер загрузил JS, CSS и шрифты из образа. Все четыре аккаунта вошли. Проверены поиск «Расписание», оценки, уведомления, заявка с ответом службы, отзыв к версии работы, режим чтения и пять мобильных разделов. Второй студент получил 404 при запросе чужой заявки и двух файлов.

После остановки и запуска веб-процесса совпали контрольные суммы 73 таблиц. В повторном сеансе Chrome открылись сохранённые ответ и отзыв, совпали SHA-256 двух вложений. Архив `pg_dump` восстановлен через TLS в другую пустую БД под отдельной ролью. В исходной и восстановленной БД сравнили десять таблиц, в том числе учётные записи, сессии, вложения, фотографии и консультации. Условия реального облачного запуска и проверки описаны в [руководстве оператора](../deploy/RENDER.md).

Вход на отдельное вымышленное имя получил HTTP 429 после пятой ошибки, в том числе при смене сетевых метаданных. Django выводит предупреждение Axes об отсутствии IP в ключе. В этой конфигурации все запросы одного логина суммируются. Ещё два предупреждения относятся к HSTS для субдоменов и предварительной загрузке HSTS. На поддомене провайдера действует HSTS для самого сервиса.

После исправления поиска пройдены 12 адресных серверных проверок. В Chrome и Firefox оба студента нашли «расписание» через настоящий endpoint и перешли к своим сведениям; преподаватель — к своему расписанию, служба не получила студенческий маршрут. Проверены основные разделы, регистр/ё, словосочетания, префиксы, пустой результат, правильная ссылка всех оценок и отсутствие модели.

В обоих браузерах проверены пустой статус уведомлений, задержанный ответ, быстрые переключения, ошибка и повтор в обычном виде и двух палитрах. Подтверждённые строки не сдвигаются из-за индикатора. Профиль осмотрен для всех ролей при 1920/1366, коротком desktop, 360/320 px и 200% текста: границы, внутреннее прокручивание, клавиатура, Escape, внешний переход первым кликом, реальный выход и очистка при смене контекста. Отдельно проверен настоящий zoom Chrome 200%.

Сервер уведомлений, импорт, бронирование, инспектор файлов и зависимости не менялись: соответствующие прошлые проверки переиспользованы. Три прежних падения исторических тестов архива остаются указанным ниже ограничением. Ускорение загрузки по смене оформления не заявляется. ## Оболочка, уведомления и чтение — 14 ноября 2026

На действующем локальном приложении измерены три перехода в каждую сторону до и после исправления. История: 2,55–2,74 → 2,04–2,16 с; входящие: 2,32–2,43 → 1,61–1,75 с. Первый наблюдаемый кадр сообщения ожидания — 12,5–15 мс. Это небольшой сравнительный набор, без очистки кешей ОС/БД и без заявлений о процентилях или нагрузочной производительности. Число SQL-запросов уменьшилось с 142/143 до 72/73. Значимая серверная задержка остаётся; индикатор не выдаёт её за мгновенную загрузку.

Chrome и Firefox проверили отмену, повторный клик, Back/Forward, ошибку и повтор, сохранность ввода/файла и ответ предыдущего аккаунта. Отдельная добавленная задержка 2 с не входит в замеры производительности. Проверены настоящий клиентский timeout и 500, denied/quota/corrupted storage, вход и публичная ошибка. Актуальные серверные проверки подтверждают границы истории, подпись/read-all с поздним событием, версию автоматического прочтения, CSRF и условные проекции. Три старых теста прежнего архива падают одинаково на исходном коде и кандидате; это сохранённое ограничение исторического suite, а не новый PASS.

Осмотрены основные студенческие страницы и рабочие места обеих других ролей, загруженный редактор, настройки, календарь и фильтры. Проверены 1366/1920 и 360/320 px, обе палитры, 125%/200% текста, клавиатура короткой боковой области, reduced motion, forced-colors и пользовательские text-spacing overrides. Настоящий zoom Chrome 200% проверен через настройку браузера в отдельном профиле: CSS-ширина 1366→683, DPR 1→2, корневой шрифт остался 16px. Это отдельная проверка от размера текста сайта.

Вычисленный контраст, дерево доступности и автоматические проверки имён/ID/альтернатив дополняют визуальный и клавиатурный проход. Реальный экранный диктор, физический телефон и полная WCAG-сертификация не проверены. Импорт, восстановление, инспектор файлов, доставка писем и полный исторический suite повторно не запускались; зависимости и схема БД не менялись.

## Поиск, подготовка и консультации

Перед локальным выпуском выполнена адресная коррекция связанного пути. Новые PostgreSQL-проверки подтверждают атомарное бронирование с личной связью, повтор после потери ответа, откат сбоя связи и неудачного переноса, прежний ручной якорь, A→B→C, отмену C, несколько явных подготовок и отсутствие раскрытия плана ведущему. Проверка поиска через HTTP использует более 200 разрешённых публикаций и отдельную границу консультаций; редкое название за прежним префиксом находится, чужой и неопубликованный двойники не меняют выдачу. Проверяются ограничение совпадений, сужение запроса, нормализация и стабильные страницы. Число SQL-запросов измеряется в этом наборе, не объявляется нагрузочным тестом.

Новый проход Chrome выполняет подготовка → выбор времени → подтверждение → возврат → два переноса → возврат → отмена. Потеря ответа управляемо воспроизводится после реального сохранения. Отдельные сессии студента, службы, преподавателя и второго студента проверяют доступ; 360 px сохраняет ввод/фокус/прокрутку при обычной проверке. Firefox проверяет затронутые страницы на 360/320 px, клавиатуру и увеличение размера текста до 200%. Маршрут «Найти все оценки» показывает 22 внесённых результата с правильным фильтром, невнесённый итог доступен отдельно. Это автоматизация на синтетических данных; физические устройства и реальная пользовательская оценка не проверены.

Зависимости и миграции этой коррекцией не меняются. Прежнее доказательство чистой установки применимо в своих границах; переустановка, полный исторический suite, импорт, инспектор файлов, восстановление и инфраструктурные проверки повторно не выполнялись. Локальная модель оставалась выключенной. Три новые подлинные иллюстрации включены в [документ процесса](creation-process.pdf); исторические снимки сохранены.

Неудачные промежуточные попытки сохранены в рабочем архиве. Среди исправлений — слишком низкий приоритет поискового действия, фокус под помощником, три пограничных случая из дополнительного чтения исходников и ошибки самих проверочных скриптов. Повторный запуск затронутого случая не считается новым независимым покрытием.

Сравнение маршрутов было наблюдаемым, но не исследованием пользователей: старая форма справки требует два клика; поиск — два клика, ввод и Enter. Сокращение времени или количества действий здесь не заявляется. Польза связанного пути — возвращение к сохранённому плану и явная связь с ответом и встречей. [Протокол для 2–3 реальных участников](RESEARCH_DECISIONS.md#короткая-проверка-с-участниками) подготовлен, участники не привлекались. Сохранены настоящие автоматизированные видеозаписи; они не выдаются за смонтированный конкурсный ролик или измерение скорости человека.

## Повторить локально

Для обычной проверки новой установки:

```powershell
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
```

Для браузера установите инструменты разработчика (они не нужны пользователю кабинета). Нужен установленный Google Chrome; скрипт выбирает `channel=chrome`.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements/development.txt
.\.venv\Scripts\python.exe scripts/verify_demo.py --base-url http://127.0.0.1:8000 --credentials .local/demo-credentials.json --output .local/checks/browser-01 --read-only
```

`--read-only` не создаёт заявку или отзыв; вход и штатные отметки просмотра всё равно могут менять состояние сеанса и уведомлений. Для полного сценария уберите флаг **только в отдельной свежей демонстрации**: будут созданы заявка и отзыв к подготовленной работе. Скрипт требует новый каталог результата. При включённом, но недоступном сервисе добавьте `--provider-state unavailable`. Проверка не выполняет подбор паролей.

## Автоматические проверки на отдельной БД

Нужна заранее созданная отдельная база **`deanery_test` под ролью `deanery_test`**, без административных прав и `CREATEDB`. Её параметры сохраняются в защищённом `.local/test.json`. Не используйте working-базу: специальный test runner выполняет миграции и **очищает содержимое тестовой БД до и после запуска**. Он не создаёт и не удаляет базу автоматически.

`test.json` использует те же ключи `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `DJANGO_SECRET_KEY`, что [основная конфигурация](SETUP.md), но отдельные значения. `deanery.settings.testing` отклоняет любое другое имя БД или роли. Защита не отменяет необходимости проверить host и port: это должна быть выделенная локальная тестовая база.

Для создания новой тестовой БД можно использовать тот же скрипт с отдельным файлом конфигурации:

```powershell
.\.venv\Scripts\python.exe scripts/create_local_database.py --database deanery_test --port 5548 --config .local/test.json
```

```powershell
.\.venv\Scripts\python.exe scripts/run_tests.py --label tests.test_optional_support --label tests.test_demo_setup --label tests.test_task12_workflows.SupportContractTests --log .local/checks/unit-01.log
```

Для изменённых предметных сценариев, на той же отдельной тестовой БД:

```powershell
.\.venv\Scripts\python.exe scripts/run_tests.py --label tests.test_discovery --label tests.test_journeys --label tests.test_consultations --label tests.test_connected_help --label tests.test_demo_setup --log .local/checks/connected-01.log
```

Команда не запускает браузер. Остальные сохранённые серверные тесты находятся в `tests/`; их исторические имена — часть совместимости исходников. Общий запуск `scripts/run_tests.py` требует той же отдельной тестовой БД. Сценарии, завязанные на закрытые браузерные записи, не включены в публичный набор.

## Проверить материалы передачи

`scripts/verify_publication.py` проверяет состав по manifest, локальные ссылки, наличие migrations/fixtures/assets, запрещённые пути и размер файлов. С `--outgoing HEAD` дополнительно проверяет все отправляемые Git blobs, а не только текущие файлы. Частные секреты можно передать через `--secret-file` из закрытых JSON; значения никогда не печатаются. Это адресная проверка, не универсальный детектор любых секретов.

Редактируемый источник документа — [creation-process.html](creation-process.html). Для повторного PDF нужен Playwright и Chrome:

```powershell
.\.venv\Scripts\python.exe scripts/render_creation_process.py --output .local/creation-process-review.pdf
```

Скрипт проверяет загрузку шрифта и изображений, переполнение страниц и создаёт PDF с внутренними ссылками. Для публикации визуально просмотрите **все** страницы; автоматическая геометрия не заменяет чтение.
